# v0.6.1 剧本生成改进与验证（2026-11-14）

版本：`script-author-2`，规则引擎仍为 `0.6.0`。本轮保留原版事件日期与名称开局公开、犯人隐藏；棋盘与交互布局不变。

## 改动

模型先规划规则、人物和时长，程序在固定约束下尝试 24 个种子，选出最多 6 份合法候选；每份候选执行两条有限引擎策略，总计最多 400 命令。模型再从候选编号和分栏事实编号中选稿。所有设计文本由实际目录、配役和能力条件编译，不能用自由散文发明机制。

完整用户计划可跳过规划请求。默认规划与选稿各一次，每阶段最多一次格式或校验修复；共用 $0.12 估算预算和 180 秒等待上限，网络结果不确定时不自动重新请求模型。开局后真相冻结。

设计与试跑只保存在私密剧本。终局复盘重新核对目录事实，并核对试跑绑定的剧本哈希；编辑剧本后再润色也不会重新认可旧试跑。UI 只调整已有提示与复盘标签。

## 测试中发现并修复的问题

1. **MC 没有可达败北条件。** 初轮真实样本 MC-2 使用“层叠事件拼图”，日程的首轮 EX 上界只有 2，且没有其他败北来源，主人公会直接通过首轮。新增保守白名单判据与原始最小回归样本，拒绝该候选。同一计划与种子仍可生成其它候选。判据区分 A.I. 模拟、银弹、黑猫、兽性杀人与后续轮回初始 EX，并保留可能存在其它败北来源的剧本。
2. **选稿引用修复不明确。** 一次 BTX 补测在允许的修复后仍因 `clues` 引用不合法而拒稿。提示现在直接列出每个字段的合法编号；修复只提供所选候选的确切选项和数量规则，不回显错误模型散文，不静默更换候选。
3. **旧试跑可能被错误认可。** 编辑机制和之后润色分别覆盖哈希失效测试，旧试跑不能继续显示为当前剧本证据。

初轮自动 API 检查为 7/8 通过，但其中 MC-2 在随后规则审查中被判定缺乏威胁，不能当作质量合格样本。另一次初轮 BTX 请求返回 HTTP 503，Worker 日志显示请求取消（37.073 秒、313 ms CPU），没有具体引擎异常；同一请求编号恢复返回 `CREATION_PENDING`，未重新编剧。上述失败和拒稿没有改写成成功结果。修正后的第二轮自动批次同样为 7/8 通过：MZ-2 遇到 HTTP 503，Worker 记录请求取消（31.011 秒、411 ms CPU）。该失败也保留原记录。随后另开一份 MZ 完整自定义计划用例，固定此前已验证的规则、人物与时长，只让模型选稿，既补齐扩展覆盖，也检验省略规划请求的路径。下表列出第二轮七份成功结果与这份独立自定义结果，不能解释为八次连续请求全成功。

## 范围与限制

候选通过规则校验和有限策略试跑，不代表已达到官方精编剧本的平衡性。试跑不是最优对抗求解；设计引用也可能选到真实但与当前胜负关系较弱的资源，不能把它称为已证明的获胜路线。新的 MC 判据只排除能够证明的特定无败北组合，不是通用剧本求解器。

Cloudflare 在纯 CPU 执行时可能冻结时钟，300 ms 保护仅为尽力而为；硬边界是命令数量。额外冻结时钟压力检查使用 24 人 MC 剧本，6 个候选共 2380 条命令，无超限或执行错误。

真实测试入口：`python scripts/live-generation-qa.py --output <private-checkpoint.json>`。凭证只通过隐藏标准输入传入，检查点不得包含凭证。发布时关闭 `SITES_QA_ENABLED`，保留原有站点访问权限。
