# v0.6 规则公开、剧本生成与 AI 质量

2026-11-14。此报告记录本轮实现、验证口径与发布实测。

## 问题与范围

上一版的规则审计主要验证合法行动、结算顺序、信息投影与完整对局可推进性。它不能证明随机剧本有趣，或 AI 会发现关键胜手。本轮针对实际审查中发现的问题改进，保留现有棋盘、手牌、配色及结算演出：

- 标准事件日程错误地默认隐藏；随机剧本标题固定，两事件固定排在第 2 天和末日。
- 工坊连续生成不换种子，切换集合可能把旧默认参数当成用户指定值。
- 最后轮回的简报忽略最终战；参考策略低估移动、人工智能及记者能力，扩展规则未充分进入评分。
- 旧“AI 生成”仅修改标题与简介，模型没有设计机制剧本。
- 缺少固定质量基准、终局设计说明及反馈入口。

## 原版信息边界

官方 Masterbook 的事件说明写明玩家预先知道事件及日期，不知道犯人。基本规则第 4-7 节要求宣布事件是否发生；已发生但没有有效目标或后续效果时，也仍算发生。MZ 伪装事件按公开表上的名称显示，不因此揭示真实类型。

一手依据：

- [Z-Man 官方 Masterbook](https://images-cdn.zmangames.com/us-east-1/filer_public/d2/1b/d21bf5e1-0661-4d8d-aa02-369b4204b7db/en-tragedylooper-masterbook_lowrez.pdf)：事件说明；末尾 Script Creation Guide 的设计禁忌、误导与压力路线。
- [Z-Man 官方基本规则](https://images.zmangames.com/filer_public/bc/e8/bce8e73f-d200-4a9f-be90-b3c59b8bb330/zm7470_tragedy_looper_rules.pdf)：4-7 Incidents happen；公开结果与秘密来源的区别。
- [原作者通用 FAQ](https://bakafire.main.jp/rooper/sr_game_02_rule.htm)：事件没有产生效果时的宣布方式及通用裁定。
- [原作者 MZ 速览](https://bakafire.main.jp/rooper/sp/pdf/summary_007.pdf)：伪装事件的公开别名。
- [日文 5th 规则官方下载入口](https://main-bakafire.ssl-lolipop.jp/rooper/10th/quickset.html)：主人公之书印刷第 24 页事件阶段、第 40 页人工智能能力。

实现默认公开名称与日期，继续隐藏犯人、配役、所选 X/Y 和未公开的效果来源。明确设置为 hidden 的旧存档或自定义剧本保留原意；缺省可见性按原版 public。人工智能模拟沿用“目标在拒绝前声明，只结算效果”的边界，不算实际事件发生。

## 剧本来源与冻结

| 来源 | 机制如何确定 | 公开给开局玩家的内容 |
| --- | --- | --- |
| 起始剧本 | 原有官方 FS 教学剧本 | 原版公开表 |
| 精选剧本 | 四份固定原创设计，FS / BTX / MZ / MC 各一份 | 标题、简介、集合、长度等摘要；设计说明终局解锁 |
| 快速随机 | 带硬约束的种子生成器 | 公开投影，不含种子和完整答案 |
| AI 编剧 | 模型输出完整剧本及独立设计摘要，经过校验后保存 | 公开投影；完整稿和设计说明只在服务器 |
| 工坊草稿 | 用户编辑、导入或生成 | 作者可看全部真相，界面明确提示 |

随机生成增加短局、标准、长局范围，显式设置优先；不再固定两事件日期。名称来自中性词组，与秘密配役无直接关联。普通盲开局的种子由服务器系统随机源产生，公开生成 ID 不再带种子；手填种子是复现功能，不提供防作弊保证。

AI 编剧只可使用目录支持的 ID 与机制，不支持的特殊规则不能靠文字绕过引擎。模型必须同时提供规则、人物、配役、事件及犯人、天数和轮回，以及私密的主要威胁、反制、线索和轮回安排。校验覆盖硬约束、结构及静态质量风险，公开文案另行隔离生成；普通问题最多一次修订；人数或日期的结构错误可在固定合法背景后最多修订两次，随后独立核对设计说明。全过程最多四次请求、180 秒，总预算仍为 $0.12。失败时不创建对局，不静默改成另一份随机剧本。

通过的剧本随对局固定，跨轮回不根据玩家操作修改真相。AI 编剧元数据保留版本、内容目录指纹及剧本摘要指纹用于复核；普通玩家不收到这些秘密输入。重复恢复同一创建请求使用请求回执，避免重复付费编剧；不同参数不能复用同一回执。

AI 润色是独立操作，只改已有剧本的标题与简介，输入只包含公开舞台及主题，不发送原始配役、犯人、私密设计或原有可能剧透的文案。

## 静态质量筛查与精选设计

`src/script-quality.mjs` 区分结构错误与设计风险，检查未登场犯人、没有实际效果的安排、调查信息不足、学习窗口过短、仅能依赖最终战的组合等。MC 的黑猫事件仍可能增加 EX，不能一律当作无意义；有最终战的集合也不要求每份剧本都必须通过轮回存活获胜。FS 没有最终战，需要可执行的轮回反制。

`accepted` 与分数是静态筛查结果，不是模型置信度、胜率或平衡认证。模型写出“有反制”不能替代引擎路径验证。详细风险报告可能包含剧本答案，只供服务器检查与终局复盘。

四份原创精选剧本：

| 标题 | 集合 | 定位 |
| --- | --- | --- |
| 长夜未熄的灯 | FS | 入门的地点威胁与能力范围观察 |
| 风铃背后的回声 | BTX | 多条压力线与跨轮回记录 |
| 没有署名的信封 | MZ | 公开名称、真实效果与扩展调查 |
| 第二次钟声之后 | MC | 主动放行事件与 EX 的权衡 |

针对每份剧本运行两条由合法命令组成的路径，验证设计压力可以造成剧作家胜利，基础反制可以造成主人公胜利；MC 反制路径需要让事件发生并达到足够 EX。它们是机制与可执行性样例，未证明面对最优对手时的平衡，也未冒充已完成真人试玩。

## AI 决策

- 修正最后轮回的目标描述：FS 与存在最后的战斗的集合分别处理。
- 输入只包括当前集合的全部可能规则与出演人物；不能按秘密中实际选中的 X/Y 裁剪主人公词典。
- 主人公先比较可获胜能力、救命移动、即时危险、调查收益与一次性资源；剧作家依据实际规则、配役与日程比较主要威胁、备用路线、常见防守以及暴露的身份线索；作者创作说明不进入任何席位的决策输入。
- `suggestion` 和 `tacticalOptions` 明确为有限启发式参考，不再无条件背书。合法佯动仍然合法，不简单删除所有无效果动作。
- 结构化记忆保存假说、证据日志编号、目标与问题；证据编号必须存在，没有证据的假说只能低确信。引擎记录的事实与模型假说分开。
- 主人公笔记按本局讨论设置共享；只在轮回间讨论时，不即时共享本轮新记忆。剧作家笔记和私密设计不进入主人公输入。
- 三牌规划、最终战和复杂能力选择使用思考模式，普通选择采用快速模式；无选择的结算仍由规则引擎执行。
- 输出仍限合法候选编号；格式、截断、候选或证据错误可修复一次，修复请求强制关闭思考并使用 1,800 token 短 JSON 上限，避免同配置重复截断；状态改变后拒绝过时回答。供应商网络结果不确定时暂停，不自动重复请求。

战术测试与对局规则测试分别记录。关键案例包括先前“人工智能可模拟银色子弹获胜，而参考策略跳过”的漏胜局面、移动避免独处死亡、记者与 EX 的作用、最终战配役约束及主人公信息隔离。有限战术通过不代表模型在所有对局中都会选择最佳走法。

## 终局复盘与反馈

对局结束后才能访问设计说明、真实规则、公开关键线索与反制建议。未结束时复盘和评价接口拒绝请求。玩家可评价有趣、偏易、偏难、线索不足或重复感强，记录关联剧本指纹；反馈入口本身不自动改变当前剧本，也不意味着已经训练或校准了生成器。

正文和模型文案在前端按文本转义，不作为 HTML 执行。进行中的公开回放、动画帧与导出继续移除私密设计、角色分配、犯人及模型私有记忆；终局全解答视角按揭晓权限显示答案。

## 真实调用中发现并修复的问题

首轮编剧在思考模式 + 8,192 token 上限下，FS、BTX、MC 均两次截断；MZ 的一次平台响应为非 JSON 503，相同创建回执恢复为处理中，没有自动重复调用。编剧已改用非思考模式输出完整结构化设计，每项设计摘要建议 50–150 字。首次新模式测试 FS、BTX、MC 创建成功，MZ 的一份候选未通过质量校验。最终错误现给出最多三条有限校验原因，仍拒绝无效剧本，不静默替换随机剧本。

QA 驱动另修正了非 MC 视角没有 EX 字段的断言；已通过相同创建回执找回 FS / BTX 原对局，没有重新编剧。上述早期失败与后续通过分别保留。

DeepSeek 参数口径对照官方 [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。模型截断是本次实测结果，不能把默认预算或思考模式当作质量保证。

MZ 的后续失败诊断明确为 `roles.immortal` 人数不符，说明模型把配役数量约束理解错了。修复反馈将给出所选规则的精确角色人数范围和当前人数，并明确人工智能占用已有配额、`maxCount: null` 不表示零配额。该改进不改变规则验证器。

最终增加独立设计核对：机械稿先通过规则校验并冻结，审稿输入只保留本稿实际选中的规则、人物、角色及事件目录。模型只可改设计说明，不能改机制；审稿输出不合格则不创建对局。它能减少混淆目录的错误，仍不是自然语言正确性或平衡性的证明。普通事件不自动公布犯人，但告白与封闭之环的明确效果保留。

旧样本说明中的已知错误还包括：FS 把不安扩大错误地作用于地点并前后写错犯人；MC 把医生能力写成反制暗跃；MZ 写错伪装事件的暗跃门槛，并建议模拟日程外事件。机制 JSON 通过规则验证不意味着这些文字成立。最终采用独立目录核对以减少这类错误；仍保留「未经人工试玩」标记。

## 最终编剧采样口径

加入最终公开文案隔离前的编剧实现下，共发送 9 次未指定 X/Y 的建局请求（仍指定短局、天数、轮回、事件数等测试约束）：FS 第 3 次成功，BTX 第 1 次成功，MZ 第 2 次成功；MC 3 次均拒稿。另以进阶设置指定 MC 的 X/Y 和出演名单，1 次请求成功，模型仍负责配役、事件、日期与设计。每次请求内部可有受限修订，不能把“建局请求数”当作供应商调用次数，也不能把重试后的成功当成首次成功率。

失败包括自动公开犯人的文字、公开简介含规则/角色名、A.I. 被分配为普通人、误导者配额、重复犯人及愚者未担任犯人。所有失败均拒绝创建对局，完整记录见 `v06-author-reviewed-qa.json`；指定规则的 MC 单独记录在 `v06-constrained-mc-qa.json`。最终 4 个已接收样本只能证明这些样本成功生成，不足以证明自由编剧稳定；MC 自由编剧成功率是本次明确未通过的质量目标。界面以“试作剧本 · 尚需试玩”标识。

真实 AI 决策验证与编剧采样分开：此前 FS 和 MC 两场完整 DeepSeek 对局分别为 38 和 31 次供应商调用，两个战术案例各 1 次；71 次调用的应用保守费用估算合计 $0.257703，**不含编剧费用**，不是供应商账单。编剧费用受每次 $0.12 上限约束，但本轮接口没有提供独立编剧用量账本，不能从潜在调用预算推算实际花费。

## 独立审查残余及最后隔离

不能把独立模型审稿等同于正确性证明。四份 `catalog-grounded-1` 样本均已对照目录与引擎复核，仍发现：

- FS：把“查明真相”写得像获胜途径（FS 无最终战）；建议降低神社地点暗跃对本稿人物暗跃/死亡威胁无直接反制作用，并提到未出演的住院患者。
- BTX：真实 `contract` 检查巫女人物暗跃，说明却围绕神社地点暗跃布局；因果之线不继承友好，旧友好只令下一轮回不安增加。题名与简介还以“契约”暗示真实规则，并写错人数。
- MZ：第一轮初始没有关键人物，却要求培养关键人物；EX 应从上轮死者中选一名，文字容易被读成全员转换。主要能力门槛和实际规则叙述较旧样本改善。
- MC：作为偏执狂的医生必须拒绝友好能力，却被列为可依赖反制；A.I. 的计数特性用于真实事件发生判断，不能当作模拟效果的触发门槛。反制仍缺少确保 EX≥2 的具体方案。

据此作最后隔离：公开题名与简介不再采用知道秘密配置的模型原稿，改由只读取公开信息的中性文案生成；用户明确指定题名仍保留。所有对局 AI 停止接收未经验证的创作说明。终局页面先展示实际所选 X/Y 的目录效果，再将模型文字明确标为“AI 创作设想”，提示以实际规则和速查为准。目录效果不能被私密设计字段覆盖。

这些隔离由最终自动化回归验证；真实调用记录保留隔离前样本，不能伪称旧稿的问题已经被模型自行修正。固定精选剧本的 8 条合法胜负路径是目前更可靠的可玩性基准，AI 自由编剧仍为试作功能。

最终应用源码冻结后，449 项测试零失败、零跳过；最新打包 Worker 9,839,653 字节，SHA256 `75e2ce2e569f98b6884caa192758aceea9bd21830941a2be63ddd0fd0d100561`，11 项应用服务测试及 13 项冒烟通过。汇总见 `v06-release-summary.json`。
