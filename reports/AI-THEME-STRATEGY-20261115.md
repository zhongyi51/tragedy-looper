# v0.7：主题与 AI 策略验证

本次检查用户报告的两个问题：主题未体现在可见剧本中，以及两边 AI 会作出明显不合理的选择。保留现有棋盘、手牌、动画和原版事件公开规则；界面只补主题说明与输入长度限制。

## 根因与修复

### 主题被中性模板覆盖

旧版已把主题传入规划和选稿提示，但最终 `publicAuthorCaption` 始终用种子标题与固定简介覆盖输出。用户看不到主题生效。

`script-author-3` 为显式非空主题增加一次独立公开文案请求，只提供主题、四个固定地点及可选用户题名。它看不到秘密规则、角色、犯人、候选评分或试跑；文案也不是推理证据。空主题不增加调用，用户题名优先。主题继续影响规划与选稿偏好，不改写机制。通常有主题三次请求，最多五次，仍共用 $0.12 与 180 秒限制。

### 决策输入与执行存在实际错误

- **阶段信息错误**：末日能力阶段仍声称“还剩一次出牌机会”。真实模型据此打算稍后补救。现在按阶段和席位计算剩余盖牌数量，末日能力阶段明确没有新的出牌机会。
- **跨阶段判断被当作简单选择**：治疗师只有四个目标，却需要同时计算不安、事件门槛、EX 和轮回末条件。旧快速模式反复压住本应放行的事件。现在给出准确前后数值、明确哪一方败北，并按风险启用推理。
- **公开推断没有形成可用约束**：已知角色、规则 X 和人数可以排除部分规则 Y；旧启发式主要依赖不会直接公开的 Y。现在仅从席位公开投影筛选可行组合，保留 MZ 伪装与 BTX 暂时变身例外，不能读取隐藏答案。
- **风险提示顺序不当**：旧版优先强调高不安，容易掩盖当晚连环杀手独处风险。现在明确今日及余下真实日程、条件性死亡威胁；无事件且无已知角色危险的临界清理只是普通维护。
- **三牌执行被截断**：三个候选编号互不相同，不保证牌或目标互不冲突。旧版可能只执行合法前缀。现在逐张检查整组，任何后缀不合法都会拒绝全部并最多修复一次。
- **单牌参考不等于整组计划**：现在提供最多三组完整方案，分别试两种只使用公开信息的主人公应对，共最多 384 次引擎命令；保留整组协同，修复缓存遗漏轮值、事件认知与翻牌历史的问题。两种防守不是穷尽搜索。

`decision-4` 对盖牌、最终战与跨阶段风险使用 low reasoning、最多 8192 token。关键决策修复保留推理；剧作家三牌请求另有窄例外：若自由组牌截断、JSON 错误或牌组冲突，唯一一次修复请求改为从最多三组已验证合法方案中选一个编号，1200 token、快速模式，仍由模型选择整组。不再次发送九十个散动作，不自动替模型执行机器人走法。理由保持简短，记忆按需输出。网络失败仍不自动重试，每局预算保持不变。

真实三牌请求出现超过旧 4096 上限的输出用量，为扩大上限提供了依据；一次中间版本请求在 8192 上限下修复后仍被截断，最终按规则暂停。因此仅增加推理预算并不够，还需要缩小修复时的决策范围。不能仅凭等待时间推断截断；最终 QA 记录明确的修复原因与 token 用量。

## 测试方法与结果

| 检验 | 结果 |
| --- | --- |
| 最终完整自动化回归 | 526/526 通过 |
| 四集合离线压力检查 | 240/240 正常结束，19,819 条合法指令；规划最高 234/384 次，0 次路径截断 |
| 真实主题生成 | 两种主题 2/2 通过，含用户指定标题 |
| 高 EX 治疗师判断 | 旧版 0/3；新版 3/3 |
| 公开线索推断 Y 后避免银弹失败 | 旧版 1/2；新版 2/2 |
| 完整三牌及所有单张反制 | 旧版 0/3（含一次模型错误）；最后修正后正常请求 2/2，每次均覆盖 80/80 应对 |
| 真实截断故障注入 | 1/1；首请求故意限制为 1 token，唯一一次修复由模型选择完整三牌，覆盖 80/80 应对 |

正常三牌复测与故障注入单独统计。其余局面包括立即杀主人公、杀关键人物、地点阈值、低 EX 治疗、银弹获胜、移动救援、地点清计数与最终角色配额，均有真实通过记录。最后一次提示改动只影响剧作家三牌修复，其他已验证决策路径未改变，故未重复付费调用它们。这里没有把来自不同修订的结果伪装成一次全通过的批次。

完整十项初始基准为 8/10；`decision-3` 的扩展复测有一次修复后仍截断。`decision-4` 的首次三牌修复又出现一次供应商 HTTP 400；检查发现新对话缺少 [DeepSeek JSON 模式要求](https://api-docs.deepseek.com/guides/json_mode/)的 JSON 字样。已补提示与接口契约测试，并通过上述真实故障注入验证。全部失败记录保留，不因后续通过而删除。


全部战术局面由经过验证的剧本和完整合法操作历史建立；没有直接篡改模型局面的身份或计数。评分在本地规则引擎中重放实际返回指令，并使用固定后续操作。三牌局面检查全部 80 种合法单张反制，其余两位主人公采用预定佯动；这不等于同时对抗三位最优玩家。

中间 `decision-2` 批次也保留：核心十项仅 9/10，追加治疗师两次都错，主人公救援出现一次退步。它不是最终发布依据。定位阶段信息错误并调整推理策略后，才重跑最终批次。

两种真实主题分别得到《末班电车的雨声》与用户指定的《雪停之后》。前者简介呈现雨夜、电车与四地点的声音意象；后者呈现初雪与旧剧院氛围，题名保持原样。人工复核未发现配役、犯人或所选规则泄漏，也没有改变实际可行动地点。共七次编剧请求，其中一稿有一次选稿修复，估算费用 $0.042449976；规则、设计引用、公开投影和预算检查均通过。

自动化测试、有限策略模拟和这些小样本真实决策不能证明整局胜率、最优对抗下的平衡，或已达到熟练玩家水平。复杂决定可能比快速模式更慢、消耗更多 token；预算与超时仍限制每次执行。

## 复现

```sh
node scripts/test-all.mjs
node scripts/strategy-soak.mjs --games-per-set=60 --seed-start=500 --days=4 --loops=2
python3 scripts/live-strategy-v2-qa.py --label candidate --output strategy.json
python3 scripts/live-strategy-v2-qa.py --extra-inference --ids mc-hero-infer-y-before-silver --replicates 2 --output inference.json
python3 scripts/live-theme-v3-qa.py --output themes.json --fixed-title '雪停之后'
```

真实脚本通过隐藏 stdin 接收站点访问凭据，复用服务端 DeepSeek 密钥；不会把凭据写入报告。QA 存档隔离于用户存档，付费错误不自动重采样。发布结束关闭 `SITES_QA_ENABLED`，普通接口继续要求用户身份。

本次结果见 [逐项真实对照](v07-live-strategy.json)、[主题实测](v07-live-themes.json)与 [240 局压力检查](v07-strategy-soak.json)。逐项对照保留失败、中间版本、修复次数及最终调用 token 用量，费用是应用估算，失败请求可能另有用量。
