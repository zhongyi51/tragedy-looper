# v0.2.2 连接恢复与自动结算验证

日期：2026-11-09（北京时间）。

## 问题与修复

- 客户端原先直接 `response.json()`，收到登录页或网关 HTML 时抛出 `Unexpected token '<'`。现先检查 HTTP 状态、重定向、内容类型及正文，区别登录、网关、损坏 JSON 与网络异常，不向玩家展示解析堆栈。
- 检查该次反馈前的生产记录：到达 Worker 的行动请求均为成功响应；模型请求约 2.4–4.1 秒，原强制结算请求约 0.6 秒。未取得报错当次的 HTML 正文，不能确定它来自登录门禁还是其他上游网关，也未复现对应的 Worker 崩溃。
- 不确定的行动响应先通过 GET 读取当前存档，不自动重发付费请求。服务端仍处理中或同步失败时禁止继续提交；重新登录采用 Sites 官方顶层入口，返回后恢复当前对局。
- 原实现单候选动作虽不请求模型，仍占一次 `ai-step` 往返。现在一次提交后连续执行确定性步骤，在真实能力、拒绝、事件目标等选择处停止；旧存档通过 `/advance` 恢复，不调用模型。
- 自动链的中间状态和命令与最终状态在同一事务持久化。可见变化按玩家视角过滤后用于动画，回放仍逐步保存；不公开额外的秘密能力信息。
- UI 集中当前阶段与主要行动，四个地点采用不同底色，强化选牌/可盖放目标，减少重复按钮，移动端优先展示棋盘。

## 验证

- 最终自动化测试共 **130 项，130 项通过**，其中保留 500 局随机规则流程。

- 自动化覆盖：HTML 200/502、登录重定向、业务 403、损坏 JSON、连接中断后的只读恢复；确定性阶段零模型调用；真实选择保留；逐步回放、幂等重试不重复计费、整链事务回滚；保留旧的规则及可见性测试。
- 浏览器实际操作：主人公选横移并盖在医生上，补齐六张后统一翻牌，医生移至神社，计数器自动结算并进入剧作家能力阶段，无须额外点击“AI 结算”。
- 生产验证使用隔离 QA 对局与已有服务端模型配置，不操作玩家对局。两份剧本均为两日、单轮回，验证流程而非策略胜率。

本次没有修改事件隐藏约定或放宽登录权限。有限验证不代表所有网络环境、规则扩展或模型策略均已覆盖。
