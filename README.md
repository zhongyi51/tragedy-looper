# 时隙 · 惨剧轮回模拟器

可本地运行的中文桌游模拟器：确定性规则引擎、DeepSeek 剧作家/主人公、独立席位观察、官方人物素材、音效、剧本编辑生成、自动存档、分支和离线回放。

v0.3 重写了整个前端（全视口棋盘、手牌与选择面板、情报/记录/推理/速查侧栏、可视化剧本工坊、手机布局），AI 剧作家每天一次性规划三张牌，离线机器人改为组合前瞻。v0.2.2 将无须选择的规则结算自动推进，补充连接异常后的存档恢复。v0.2.1 修复事件日程可见性、棋盘盖牌动画和 AI 异常恢复；v0.2 提供 ChatGPT Sites 私有托管适配（Worker + D1）。托管配置见 [DEPLOYMENT.md](DEPLOYMENT.md)。公开源码不携带 API 密钥、个人存档或私人站点配置。

## 启动

需要 Node.js 24 或更新版本。没有第三方 npm 依赖，不需要安装或构建步骤。

Windows 双击 `Start.cmd`，在本地终端隐藏输入 DeepSeek 密钥，或直接回车使用离线练习机器人。也可在项目目录运行：

```powershell
.\Start.ps1
# 完全离线，不询问密钥
.\Start.ps1 -Offline
```

打开 [本地游戏](http://127.0.0.1:4317)。启动脚本只把密钥保留在当前服务进程环境，退出后恢复原环境，不写入文件。也支持预先设置 DEEPSEEK_API_KEY 后执行 `node src/server.mjs`。不要把密钥添加到前端文件、导出文件或版本库。

服务仅绑定 127.0.0.1；默认端口 4317。存档和用量账本在 runtime/games.sqlite（SQLite WAL）。保留 runtime 目录和浏览器站点 Cookie 可继续自己的对局；备份 SQLite 时应先停止服务，或同时正确处理 WAL。

## 玩法与功能

- 档案室：选择立场（主人公 / 剧作家 / AI 观战）与剧本（官方 FS 教学剧本、新生成的 FS / BTX、工坊草稿）；存档列表显示轮回、日期与胜负，可随时继续。
- 棋盘：四个地点占满视口，人物卡随人数自动缩放，显示友好 / 不安 / 暗跃、不安临界警示、已确认角色、护卫与死亡。选中手牌后，合法目标高亮并预告效果（“→ 神社”“禁入医院”“不安 +1”“无效”）；盖放后不能撤回，六张牌齐后统一翻面，当天结算过的牌保留在目标上。
- 行动坞：底部固定显示“现在该谁做什么”、今日六张牌的进度、你的手牌或全部合法选项（按能力 / 人物分组，悬停高亮对应人物或地点）。主人公视角可点击席位预览另外两套手牌。数字键 1–9 选牌，Esc 取消。自己出的牌立刻落到棋盘上，可以马上选下一张，不等服务端也不等动画；服务端在后台按顺序确认，最后一张出完才等待结算。若某张牌没有确认成功，它会从棋盘上收回并提示重试，排在后面的不会再发送。
- 对手：建局时选择 DeepSeek 或离线练习机器人。默认开启“对手自动”，轮到对手时自动推进至你的回合；关闭后手动点击“让 AI 继续”，可随时暂停，已发送的一次调用仍会完成。“代走一步”让机器人替你走当前这一步。练习机器人是明确标识的离线启发式策略（剧作家对三张牌做组合前瞻，主人公只读公开信息），不冒充模型。
- 侧栏：情报（事件日程、已确认角色、生效中的规则标记、预算）、记录（按轮回、日期和阶段分组的公开日志，夹带 AI 主人公的公开理由；AI 剧作家的理由始终不展示）、推理（见下）、速查（当前惨剧集合的主副规则、角色、事件）。手机上为抽屉。
- 结算播放：服务端为每一条结算结果返回一帧，界面逐条播放——谁出了牌、翻牌、每次移动、每个计数变化、被禁止的效果、能力、拒绝、事件、死亡——当前结果的人物或地点高亮，其余压暗，底栏显示这一步的说明和此前几步。可切换 1× / 2× 或“跳过”。每天结束时停在“第 N 日结束”，列出当天的死亡、事件与身份揭示，由玩家点“进入第 N+1 日”（或回车）；轮回失败时停在失败横幅。AI 观战时自动继续。被禁止、互相抵消（同一天两张暗跃禁止）或被无视的牌会在人物上盖一枚印记，牌面划掉并保留到当天结束；轮回失败、主人公胜利、剧作家胜利各有不同的全屏演出，棋盘随之变色。系统开启“减少动态效果”时仍逐条显示，只是不做位移动画。终局后可“揭晓真相”查看配役与事件。
- 推理表：主人公专用，只存在本浏览器。用“排除 / 认定 / 存疑”三种标记填人物 × 角色表和主副规则；表头显示每个角色在仍可能的规则组合里的人数范围，已公开的身份、拒绝或接受过能力的人物、规则里没有的角色、人数已满的角色会自动填好并锁定。“推论”列出只剩一种可能的格子，可一键采纳；标记互相矛盾时给出提示。可为每个事件猜犯人，猜测会以标签显示在棋盘人物上；最后的战斗里，你认定和排除的角色直接标在选项上。另有按轮回整理的线索时间线（标出每条线索发生在第几日的哪个阶段）与自由笔记。轮回失败时，横幅、时之狭间和线索里都写明失败发生的时间与公开事实——某人一死轮回立即结束，或最后一天结束时判定失败及当时场上的暗跃；按规则，背后的规则和角色不公布，要靠这些线索推理。
- 规则手册：五分钟上手、行动牌、24 名人物（原始卡面与中文能力）、FS / BTX 的全部主副规则、角色与事件。
- 剧本工坊：可复现种子的约束生成、AI 标题 / 简介润色；可视化表单编辑配役、角色、事件与犯人，实时显示规则要求的角色数量与结构校验，也可直接改 JSON；JSON 导入导出、公开 / 私密打印 HTML 页、以草稿直接开局。
- 回放：单步、拖动、自动播放、方向键；公开或终局全解答视角；导出 JSON 或独立 HTML 离线回放（不需要服务、网络或 API，使用文字棋盘而非嵌入全部立绘）。
- 分支：终局后可从回放的历史位置创建新对局，再作不同选择；新分支有独立预算。

本地人类主人公控制三套牌；AI 主人公为三个独立笔记和请求视角。当前版本没有远程联机、好友邀请或语音聊天。房间有交流规则字段，AI 默认各自决策，尚未加入轮回间自动讨论模型；不影响规则流程，但限制协作强度。

## 规则范围

基线为日文 5th 的 First Steps 与 Basic Tragedy Χ，包含24名基础人物、14种不同角色、16项主副规则、9类事件和双方基础牌组。原始卡面和中文能力可在规则手册中查看。扩展集合、额外11名扩展人物和自定义特殊规则未启用，导入时会拒绝不支持的规则。

FS 没有最后的战斗；BTX 最后指认逐人进行，首次错误即失败。模型只能选择引擎提供的候选编号，不能改变配役、犯人、计数器或胜负。没有合法效果的事件与没有发生的事件分别处理。

## AI 与预算

使用官方 `https://api.deepseek.com` 和 `deepseek-flash`，非思考模式进行低成本决策。固定规则形成稳定前缀，服务记录原始 prompt/cache/completion token 用量；供应商缓存命中是尽力而为，不保证命中。

每局默认预算 $0.50，可在建局时设置 $0.01–$10。请求前按 UTF-8 输入字节上界和最大输出预留，结束后按用量结算估算；超时可能已计费，保留预留且不自动重试。JSON/候选错误最多修复一次，仍失败则暂停。费用明细在终局开放，避免从秘密决策调用数量推断角色。

UI 的金额为保守费率估算，不是供应商结算账单；当前费率假设为每百万 token 普通输入 $0.30、缓存读取 $0.006、输出 $1.20。正式计费以自己的 DeepSeek 账户为准。用量和测试报告可以复核估算，没有把订阅额度当作 API 余额。

## v0.2.1 规则与交互约定

- 本站按用户要求隐藏事件日程名称：主人公和公开观战只看到日期，剧作家看到事件类型及犯人。已发生事件的公开结果仍记录；未发生事件不泄露名称。公开 JSON、打印、回放及主人公 AI 采用同一边界，旧存档在读取时脱敏。此处属于本站可见性约定，不宣称原版所有版本都隐藏日程名称。
- 所有行动牌都可盖在地点上；地点只接受暗跃相关效果，移动、友好、不安等牌是无效果佯动。依据[原作者 FAQ Ca01 / Ca02](https://main-bakafire.ssl-lolipop.jp/rooper/sr_game_02_rule.htm)。不将合法佯动误判为非法动作。
- 牌背直接落在棋盘目标上，标明幕 / A / B / C。六张齐后统一翻牌，动画结束后继续推进；减少运动模式和动画异常不阻断规则操作。
- AI 只能返回当前合法候选的整数编号，服务器检查结构、候选和当前局面。格式错误最多修复一次；网络不确定性不自动重试，出错保留局面并展示可恢复提示。

## v0.2.2 自动结算与连接恢复

- 每次行动提交后，服务器连续执行不需要选择的规则步骤。移动、计数器、强制能力与无目标选择的事件不再逐项等待 AI。真实的可选能力、拒绝、事件目标及会影响结果的邪教徒选择仍由对应席位决定。
- `/advance` 只执行确定性规则，不发送模型请求。可恢复停在旧版结算阶段的存档；到达真实决策边界时停止。所有中间规则步骤仍保存为回放快照，前端依次展示可见变化。
- 接口响应先检查 HTTP 状态、重定向和内容类型。登录页面、网关 HTML、损坏 JSON 与网络中断不再直接显示 JavaScript 解析错误；行动结果不确定时先读取当前存档，不自动重发行动或付费请求。
- Sites 登录失效时使用平台的顶层登录入口，返回后恢复已保存的对局。浏览器不持有模型 API 密钥，不绕过站点访问权限。

## 体验更新：AI 强度与界面

- 每次 AI 决策附带按席位生成的局势简报（`strategicBriefing`）：剧作家看到各事件犯人的不安差距、关键人物、杀手同处与移动建议；主人公只看到公开计数器、事件日期与已确认信息，测试保证其不依赖秘密配役。
- 模型输出解析容忍代码块和前后杂讯，只接受 JSON 对象；仍无法解析才进入一次修复流程。

## v0.3 界面与对手

- 前端不再是单个脚本：渲染函数只返回 HTML 字符串，会话控制器与演出控制器的依赖（请求、存储、DOM 效果）全部注入，因此界面逻辑由 `node --test` 直接导入模块验证，不依赖浏览器。页面按区域比对 HTML 后才替换，输入焦点与光标不丢失。
- AI 剧作家在每天开始出牌时一次请求给出最多三张牌（仍然只能返回互不相同的合法候选编号，服务器逐张校验后依次执行，格式不符进入一次修复），并附带离线搜索给出的参考组合。人类主人公一人操控三套牌，因此以团队视角看到三套手牌和自己盖下的牌面；AI 主人公仍是三个独立视角。
- 视图新增公开的规则标记（主人公不死、住院患者可离开医院、被压制的事件），客户端不再从日志文本推断；进入最后的战斗时清空当日盖牌。
- 存档列表由服务器给出摘要（标题、轮回、日期、胜负），终局前不返回花费。
- 离线机器人对战基线：200 局剧本中剧作家 136 胜、主人公 64 胜，两侧都能获胜。
